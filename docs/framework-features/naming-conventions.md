# Naming Conventions

## Best Practices for Naming Test Cases and Keywords 

### a. Descriptive Names  
Use clear and descriptive names for test cases and keywords to make their purpose easily understandable.   
**Example**:  

![Platform Overview diagram](/img/descriptivenames.png)

### b. Consistent Naming Style  
Follow a consistent naming convention such as CamelCase or snake_case throughout your test cases and keywords.   
**Example**:  

![Platform Overview diagram](/img/consistentnamingstyle.png)

### c. Avoid Ambiguity 
Avoid vague names. Ensure names convey the exact action or verification performed.  
**Example**:

![Platform Overview diagram](/img/avoidambiguity.png)

### d. Use Prefixes for Keywords  
Use prefixes for keywords to indicate their category or purpose (e.g., UI_ for user interface actions, DB_ for database actions).  
**Example**:

![Platform Overview diagram](/img/prefixesforkeywords.png)
